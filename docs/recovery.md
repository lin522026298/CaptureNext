# 恢复以后如何使用

## 必须一起保存什么

新版滚动备份入口是 `archives/wechat-next/backups/paired-v3`。保留整个仓库目录、其中的身份绑定和已验证快照；不要只复制某一个 SQLite 表或凭手工抽走共享块。旧式成对仓库需要 `state` 与 `unified` 两套仓库及配套清单，不能和新版格式混用。

恢复点需要消息及来源档案、原始附件内容库和必要配套材料。经历史迁移的安装还需要 provenance；全新独立安装没有作者的历史材料，其配置明确记录这一点，不能把旧安装丢失 provenance 当作新安装略过。程序通过成套清单验证它们，不要自行拼装。默认不备份明文数据库密钥：无 key 的已解码副本可以离线读，但重新连接微信继续采集还需与指定来源匹配的必要 key／配置。图片另需的密钥也应独立受控保管。

首次独立备份后，请实际恢复到全新位置并查看一段旧会话和附件。备份写在当前硬盘不抵御硬盘物理损坏，建议额外完整复制仓库到独立介质。

## 离线只读打开恢复副本

1. 在备份界面选择已有成功恢复点，恢复到一个全新目录；保持原正式档案不动。
2. 检查恢复结果完整性状态。选择“打开恢复副本”阅读，不进入采集接管。
3. 也可安全退出当前应用后，运行根目录 `Start-CaptureNext.ps1 -Offline`，将参数指向**包含恢复回执、state 和 union 的整个恢复包目录**，不是只指向一份 `.sqlite`。

```powershell
$restored = Read-Host '已验证的完整恢复包目录'
.\Start-CaptureNext.ps1 -Offline $restored
```

同一安装目录只有一个后台。已有实例不会因第二次启动参数自动换成另一个来源；先安全退出再明确选择离线模式。离线模式不登录微信、不采集，也不默认覆盖当前档案。

## 正式状态损坏

同一安装的仓库仍在默认位置时，运行 `Start-CaptureNext.ps1 -Recovery`，从备份列表选择恢复点并恢复到新目录。根入口和界面当前不提供任意外部仓库路径选择。

新电脑或异盘备份恢复时：

1. 在本地新目录完整解压便携程序。只为恢复／离线阅读时，**不要先运行 Configure**，也不需要先连接微信。
2. 确保该新安装没有正在运行的实例。将独立介质上**整个** `paired-v3` 仓库复制到新安装的 `archives/wechat-next/backups/paired-v3`；不要只复制 `repository.sqlite`，不要与现有仓库合并或覆盖。
3. 运行 `Start-CaptureNext.ps1 -Recovery`，选择已成功恢复点并恢复到全新目标名；等待完整核验成功后打开恢复副本。
4. 只读验看成功之后，才考虑界面提供的显式接管流程。程序要检查恢复材料和来源身份；材料不足时只能离线查看，不能冒称可继续采集。

旧式成对仓库的手动布局为同级 `backups/state` 与 `backups/unified`，需要整套保留，不能只带其中一半；普通新用户优先使用新版 `paired-v3`。

接管不会要求删除唯一原始来源。旧电脑原生记录在确认合入且恢复可用之前至少保留完整一份。不要直接把旧 WUA 文件冒充当前采集状态，也不要在运行时手动替换数据库。
